مخزن دير الأنبا بيشوي - المرحلة الثالثة
===============================================
ابدأ بملف START_HERE.txt للتركيب.

ماذا تضيف الحزمة؟
- رئيسية جديدة: المطعم / المخزن.
- كروت منتجات بالصور، والوحدة، والرصيد الفعلي والمتاح.
- أقسام، بحث بالاسم أو الباركود، وفلاتر للنقص والصلاحية.
- حدود حمراء عند نقص المخزون، وذهبية عند قرب الصلاحية.
- تفاصيل الدفعات والحركات للمسؤول المصرح له فقط.
- توريد وصرف من واجهة الموبايل، باستخدام services.py السابق.
- إضافة وتعديل المنتجات والأقسام والوحدات بالصلاحيات.
- حذف السجل الفارغ فقط. السجل المرتبط يُوقف ولا يُحذف.

المتطلبات:
store/models.py من المرحلة الأولى، والمرحلة الثانية (services.py / admin_forms.py) مركبة.
store في INSTALLED_APPS، و APP_DIRS=True، و staticfiles و CSRF و sessions و messages مفعلة.
الحزمة لا تغير models.py / services.py / admin.py / base.html / accounts/views.py / accounts/home.html.
القوالب ترث accounts/base.html الحالي، فيظل الجرس وصور الدير والترحيب كما هم.
ملف CSS الجديد يتحمل من داخل تطبيق store/static/store ولا يستبدل ملفاتك الخمسة.
لا يحتاج إلى migrations جديدة أو مكتبات إضافية.

الصلاحيات:
- الحساب النشط المسجل دخوله يشاهد المنتجات النشطة والرصيد، ولا يصرف بنفسه.
- المطور role=superadmin أو is_superuser=True له إدارة المخزن.
- المسؤول role=admin يحتاج صلاحيات المخزن، وليس دور المطعم وحده.
- لمنح مسؤول موجود صلاحيات المخزن، استبدل USERNAME باسم دخوله:
python manage.py grant_store_access --username USERNAME
الأمر يمنح صلاحيات إدارة المنتجات/الأقسام/الوحدات، والوارد/الصرف ومراجعة السجل.
لا يحول الراهب إلى مسؤول، ولا يفعل is_staff أو is_superuser.
الواجهة المخصصة لا تحتاج is_staff=True.

المطعم:
دالة accounts.views.home الحالية تظل كما هي، وتعمل من /meals/.
الرئيسية / تحولت إلى اختيار الخدمة.
في kitchen/templates/kitchen/menu.html، يمكن تعديل رابط الرجوع للوجبات فقط ليصبح:
{% url 'accounts:meals' %}
بدل accounts:home. الهيدر يظل accounts:home لاختيار الخدمة.
الروابط /kitchen/ والتقارير والإشعارات لم تتغير.

تجربة مقترحة:
1. ادخل بحساب المطور، وافتح المخزن.
2. اختر منتجًا أو أضف منتجًا جديدًا بالزجاجة، حده الأدنى 10.
3. سجل وارد 20 وصرف 10، فيصبح المتاح 10 والحدود حمراء.
4. اصرف 11 والمتاح 10: يجب رفض العملية.
5. ادخل بحساب monk: يشاهد المنتجات ولا يستطيع الصرف برابط مباشر.
6. ارجع للرئيسية وافتح المطعم والتقرير للتأكد من استمرارهما.

حدود هذه المرحلة:
- تنبيهات الألوان محسوبة وقت فتح الصفحة. لا يتم توليد StockAlert أو Notice أو Push هنا.
- مسح الباركود بالكاميرا لم يُضف. الكود المكتوب يعمل في البحث.
- طلبات احتياجات الرهبان وشاشات المرتجع والتالف والتسويات لم تُفعّل بعد.
- كل POST صحيح للوارد/الصرف يمثل عملية. JavaScript يمنع الضغط المكرر في نفس الصفحة فقط.
- هذا ليس مفتاح منع تكرار دائم على قاعدة البيانات. لا تُعِد العملية بعد قطع الاتصال قبل مراجعة سجلها.
- المخزن يستخدم وحدة واحدة لكل منتج، ولا يحوّل الكراتين إلى قطع تلقائيًا.

ما تم فحصه هنا:
- صياغة Python و JavaScript و CSS وتوازن وسوم القوالب.
- معاينات متصفح على الموبايل والكمبيوتر ببيانات تجريبية وقالب أساسي بديل للمعاينة.
- لم يتم تشغيل Django أو اختباراته هنا؛ لم يتوفر Django وتعذر تنزيله.
- هناك 38 اختبارًا مرفقًا، وليست نتيجة تشغيل. شغلها على نسخة التطوير قبل الاستخدام.
- اختبارات الويب تستخدم base.html مبسطًا للاختبار، ولا تختبر الجرس والترحيب وروابط مشروعك الفعلية.
