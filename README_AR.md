# إشعارات طلبات الدير — إضافة Django MVT

## ما الذي تضيفه هذه الحزمة؟
- جرس وعدّاد لغير المقروء وقائمة إشعارات بهوية نبيتي/ذهبي/عاجي، مناسبة للموبايل.
- سجل دائم لكل مستخدم؛ لا يستطيع المستخدم قراءة أو تغيير إشعارات مستخدم آخر.
- إشعارات فتح/إغلاق الوجبة، بما فيها انتهاء الموعد أو إيقاف آخر صنف، وأخرى يدوية.
- تحديد الكل (كل الحسابات النشطة) أو أسماء محددة لكل إرسال يدوي ولكل قائمة وجبة.
- Push حقيقي للأجهزة التي وافقت على الاشتراك؛ يتطلب HTTPS وإعداد مفاتيح وعامل إرسال.
- حالة غير المقروء منفصلة عن قبول خدمة Push: نجاح الإرسال لا يعني القراءة.
- مكرر النقر على الإرسال اليدوي بنفس النموذج لا ينشئ نفس الإشعار مرتين.
- لا تعديل في kitchen/views.py أو kitchen/models.py أو التقرير أو ملفات ألوانك.
- ملف base.html الوحيد المستبدل مبني على آخر حزمة الصور التي أُعدّت في المحادثة.

هذه إضافة تحتاج التركيب والاختبار في مشروعك. لا تحتوي على مفاتيح خاصة أو بيانات حقيقية.

## التركيب أول مرة — والمشروع المحلي متوقف
1. احتفظ بنسخة احتياطية من مشروعك وقاعدة البيانات وملف:
   accounts/templates/accounts/base.html
2. فك ضغط الحزمة. انسخ المجلدين notifications وaccounts إلى مجلد مشروعك الذي يحتوي manage.py.
   ادمج accounts ولا تحذف المجلد القديم. استبدل base.html بعد عمل نسخة احتياطية.
   لا تنسخ مجلد notifications داخل kitchen أو api.
   إن كنت قد عدلت base.html بنفسك، ادمج فقط روابط notifications.css/js وmanifest وwidget من النسخة المرفقة.
3. أضف إلى INSTALLED_APPS في api/settings.py دون حذف التطبيقات الموجودة:
   "notifications.apps.NotificationsConfig",
4. داخل TEMPLATES -> OPTIONS -> context_processors أضف:
   "notifications.context_processors.notification_ui",
   واحتفظ بـ core.site_branding.monastery_branding وباقي الإعدادات.
5. في آخر settings.py خارج القوائم أضف:
   NOTIFICATIONS_PUSH_ENABLED = False
   NOTIFICATIONS_VAPID_FILE = BASE_DIR / ".secrets" / "webpush.json"
6. في api/urls.py أضف الاستيراد:
   from notifications import views as notification_views
   ثم أضف داخل urlpatterns قبل أي catch-all:
   path("notifications/", include("notifications.urls")),
   path("notifications-sw.js", notification_views.worker_script, name="notifications_worker"),
   path("notifications.webmanifest", notification_views.manifest, name="notifications_manifest"),
   اترك روابط accounts وkitchen وadmin وmedia كما هي.
7. من البيئة الافتراضية، بجانب manage.py:
   python -m pip install -r requirements-notifications.txt
   python manage.py makemigrations notifications
   python manage.py migrate
   python manage.py init_notifications
   python manage.py check

init_notifications يثبت حالة القوائم الموجودة عند التركيب دون إرسال إشعارات قديمة.
شغّله بعد migrate وقبل تشغيل الموقع والعامل أول مرة. لا يحذف رسائل ولا يعيد ضبط حالات مسجلة.

## التشغيل
Terminal أول:
python manage.py runserver

Terminal ثانٍ، نفس البيئة والمجلد:
python manage.py run_notification_worker

اترك نافذتي التشغيل مفتوحتين أثناء التجربة.
العامل يعمل افتراضيًا كل ثانيتين: يراجع تغيّر الحالة/انتهاء الموعد، ثم يرسل طابور Push.
شغّل نسخة واحدة من العامل، خاصة مع SQLite. أوقفه بـ Ctrl+C.
للدورة الواحدة فقط:
python manage.py run_notification_worker --once

في الإنتاج شغّل العامل كخدمة تُعاد تلقائيًا عند التوقف، مع مراقبة السجلات.
runserver ليس خادم الإنتاج. للتزامن العالي استخدم قاعدة بيانات وخادم نشر مناسبين.

## تجربة الإشعارات الداخلية أولًا
- افتح /notifications/manage/ بحساب admin أو superadmin.
- أرسل عنوانًا ونصًا إلى مستخدم واحد أو اختر الكل.
- افتح حساب هذا المستخدم في متصفح آخر أو نافذة خاصة.
- افتح الجرس أو /notifications/. الإشعار محفوظ حتى إن لم يوافق على Push.
- الجرس يُحدّث كل 10 ثوانٍ عندما تكون الصفحة ظاهرة، وعند فتح الجرس أو الرجوع للتبويب.
- افتح قائمة اليوم من شاشة إعداد الوجبات؛ تتولد الرسالة بعد الحفظ الناجح.
- كرر الفتح وهي مفتوحة: لن تتولد رسالة جديدة. أغلقها: تتولد رسالة إغلاق.
- سجّل مستخدمًا آخر لم يتم اختياره وتأكد أنه لا يرى الرسالة.

## تخصيص مستلمي الفتح والإغلاق التلقائي
1. جهز قائمة الوجبة واتركها مغلقة في البداية.
2. افتح صفحة إدارة الإشعارات، ثم قسم الإرسال التلقائي.
3. اختر الوجبة والتاريخ واضغط عرض الإعدادات.
4. اختر الكل أو مستخدمين محددين ثم احفظ.
5. ارجع لقائمة الوجبة واضغط فتح الطلبات.
الاختيار خاص بهذه الوجبة وهذا التاريخ، ولا يمنع غير المختارين من الطلب.
القوائم الجديدة افتراضيًا ترسل إلى كل الحسابات النشطة، بمن فيهم المسؤولون.
تغيير المستلمين أو تفعيل الإرسال وحده لا يرسل رسائل بأثر رجعي.
المستخدم الذي يُعطّل حسابه قبل إرسال Push لن يُرسل إلى جهازه.

## تشغيل Push خارج الموقع
هذا القسم ليس مطلوبًا لتجربة الجرس داخل الموقع، لكنه مطلوب للتنبيه خارج الصفحة.

1. ضع الموقع على عنوان HTTPS صالح يمكن للموبايلات الوصول له.
   localhost/127.0.0.1 على الكمبيوتر حالة تطوير خاصة، وليس عنوان الكمبيوتر من الموبايل.
   فتح الموقع من الهاتف على http://192.168... لا يكفي لتفعيل Push.
2. ولّد مفاتيح VAPID على جهازك/السيرفر:
   python manage.py generate_push_keys --email YOUR_REAL_EMAIL
   استبدل YOUR_REAL_EMAIL بعنوان تواصل حقيقي؛ لا تتركه حرفيًا.
   الأداة تحفظ .secrets/webpush.json و.secrets/webpush-private.pem.
3. أضف .secrets/ إلى .gitignore، ولا تنسخ هذه الملفات إلى static أو media.
   احتفظ بالمفتاح الخاص على السيرفر فقط وبصلاحيات وصول مقيدة.
   لا تعِد توليد المفاتيح كل مرة؛ الاشتراكات مرتبطة بالمفتاح العام.
4. غيّر:
   NOTIFICATIONS_PUSH_ENABLED = True
5. أعد تشغيل السيرفر والعامل.
6. يفتح المستخدم الجرس ويضغط «تفعيل تنبيهات الموبايل»، ثم يوافق على الإذن.
7. iPhone/iPad: الإصدارات المدعومة من 16.4، أضف الموقع للشاشة الرئيسية
   وافتحه من الأيقونة ثم فعّل الإشعارات. يتأثر الوصول بإعدادات Focus والجهاز.
8. عند إرسال رسالة، العامل يتواصل مع خدمة Push التابعة للمتصفح.
   الإنترنت مطلوب للـPush حتى لو الموقع نفسه يعمل على شبكة داخلية.
9. إيقاف تنبيهات الجهاز لا يحذف الرسائل داخل حساب المستخدم.
10. تسجيل الخروج يعطّل الاشتراكات المرتبطة بتلك الجلسة. الرسائل التي سبق تسليمها
    لنظام الهاتف لا يمكن سحبها بأثر رجعي. عند تبديل الحساب يربط الاشتراك بالحساب الحالي.

خدمة Push هنا عبر البروتوكول القياسي؛ لا تحتاج حساب Firebase منفصل.
شكل التنبيه الخارجي والأصوات يحددها الهاتف والمتصفح. ألواننا داخل التطبيق فقط.
لا يوجد ضمان زمني لوصول التنبيه أو لظهوره عندما الجهاز أو الشبكة تمنع ذلك.
لا يعتمد النظام على رسالة Push وحدها: السجل الداخلي هو المرجع.

## Service Worker موجود بالفعل؟
الحزمة تضيف /notifications-sw.js بنطاق / ولا تخزن صفحات الحسابات أو البيانات offline.
العميل لا يحذف Service Worker موجودًا ولا يستبدله صامتًا.
إن كان عندك Service Worker مختلف في نفس النطاق، سيظهر تنبيه واضح عند التفعيل:
ادمج معالجَي push وnotificationclick فيه واضبط التسجيل بدل تشغيل ملفين متنافسين.
لا تنسخ هذه الحزمة لإزالة وظائف PWA موجودة. base.html المرفق مبني على النسخة السابقة
التي لم تكن تسجّل Service Worker.

## كيف تعمل التلقائية؟ وما الحدود؟
- post_save لـ DailyMenu يسجل مراقبة الحالة باستخدام transaction.on_commit.
- لا إرسال شبكة أثناء حفظ الوجبة: الرسالة والمستلمون ووظائف الإرسال تحفظ في قاعدة البيانات.
- جدول الحالة + رقم مراجعة ومفتاح فريد يمنع التكرار لنفس الانتقال المرصود.
- العامل يعوض تغييرات QuerySet.update التي لا تستدعي save/signals ويراجع المواعيد.
- الكتابات الجماعية السريعة جدًا التي تفتح ثم تغلق بين دورتَي العامل قد لا تنتج
  رسالة لكل حالة وسيطة؛ يتم التقاط الحالة النهائية. استخدم الحفظ المعتاد للتغييرات المهمة.
- عند تعطل العامل لا تتوقف طلبات المطعم. أحداث save المعتادة تحفظ داخل السجل؛
  Push ومراقبة المواعيد ينتظران تشغيل العامل.
- إعادة المحاولة بعد انقطاع الشبكة يمكن أن تسبب إعادة تسليم من مزود Push؛ tag ثابت
  يساعد النظام على استبدال النسخة السابقة، لكنه ليس ضمان exactly-once على كل جهاز.
- إشعارات الفتح القديمة التي أُغلق بعدها نفس المنيو تُتجاوز عند إرسال Push،
  مع الاحتفاظ بسجلها داخليًا.
- الإشعارات القديمة/المستقبلية لا تفتح وجبة اليوم بالخطأ؛ تظهر صفحة تفاصيلها.
- الروابط تفترض نشر المشروع على جذر الدومين / مثل مشروعك الحالي.
- تدعم الإضافة قاعدة البيانات default فقط في هذه النسخة.
- حد الأجهزة النشطة 10 لكل مستخدم، و5 محاولات إرسال قبل إعلان التعذر.
- توجد قائمة سماح ضيقة لخدمات Push المعروفة؛ لا تسمح بعناوين داخلية أو أي URL يرسله العميل.
  لا تضف host جديدًا دون التحقق أنه تابع لمزود المتصفح.
- الرسائل التلقائية لا تسجل اسم المسؤول الذي ضغط الزر؛ سجل actor موجود للإرسال اليدوي.
- لا تعدّل صلاحيات الحسابات أو شاشة التقارير، ولا تضف صورة من مصادر خارجية.

## الاختبارات
الحزمة تحتوي اختبارات Django للتصفية والصلاحيات والتكرار والتراجع والمعاملات
والمواعيد وقائمة المستلمين وCSRF. لتشغيلها داخل مشروعك:
python manage.py test notifications

تم فحص صياغة ملفات Python/JavaScript وقوالب Django بنيويًا، ومعاينة الواجهة
على بيانات تجريبية في بيئة إعداد الحزمة. بيئة إعداد الحزمة لم تتوفر فيها Django
أو اتصال Push فعلي؛ اختبارات Django المرفقة لم تُنفّذ هنا.
لم تُختبر هذه الحزمة على قاعدة بياناتك أو هواتف فعلية. اختبر على نسخة التطوير
وحسابات تجريبية قبل تشغيل الإرسال لكل المستخدمين.
